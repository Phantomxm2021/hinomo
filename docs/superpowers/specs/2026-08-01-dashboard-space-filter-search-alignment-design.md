# 首页空间筛选与搜索对齐设计

## 目标

统一首页与导航中的空间术语，在首页提供场地维度的数据筛选，并让搜索页输入框与首页搜索框采用同一套视觉组件。

## 术语边界

- “家庭总览”改为“空间总览”。
- “按房间查看”改为“按空间查看”。
- 桌面和移动导航中的“场地 / 场地与空间”统一显示为“空间”。
- 底层数据模型保持 `venues → spaces`，数据库表和 API 类型不重命名。
- 创建、编辑和选择数据层级时仍使用“场地”，避免把“场地”和“空间”两个实体混为一谈。

## 默认场地

- 每个用户始终有一个名为“默认”的内置场地。
- 新注册用户通过数据库触发器自动创建“默认”。
- 迁移为所有既有用户补建“默认”，但不移动、改名或删除既有场地与空间。
- `venues` 增加 `is_default` 标记；“默认”固定排在场地列表第一项，其余按名称排序。
- 新建空间与首页场地下拉框都默认选择列表第一项。
- 默认场地名称固定且不可编辑、不可删除；其他场地维持现有 CRUD。

## 首页场地筛选

- 首页标题区域右上角显示场地下拉框；移动端在标题下方保持全宽，桌面端靠右。
- 初始值为第一个场地，不提供“全部场地”作为默认值。
- 切换后同时过滤：空间数量、箱子数量、物品数量、按空间查看卡片、最近打开箱子。
- 过滤在前端基于已加载的空间和箱子数据执行；不增加额外数据库 RPC。
- 加载时下拉框显示 Skeleton；场地接口失败时保留既有首页错误与重试语义。
- 场地下没有空间或箱子时显示对应空状态，但不误报全局数据为空。

## 搜索框对齐

- 以首页 `GlobalFindBar` 为唯一视觉基准：48px 控件高度、相同圆角、边框、图标、内边距、字号和焦点态。
- 抽取共享的搜索输入外壳，首页和搜索页只负责各自的数据与提交行为。
- 首页继续保留移动端搜索按钮和桌面扫码按钮；搜索页只显示搜索提交按钮，不显示扫码按钮。
- 搜索页现有 URL、debounce、输入法组合输入和 Skeleton 行为保持不变。

## 数据与错误处理

- 新迁移只新增默认场地保障和 PostgREST schema cache 刷新，不删除业务数据。
- 默认场地创建使用唯一约束与 `on conflict do nothing`，避免重复。
- 前端场地查询继续兼容迁移未执行时的明确提示；首页不会把查询错误渲染为空集合。

## 验收

- API 测试覆盖默认场地固定排序。
- 首页组件测试覆盖默认选择、切换场地后五类数据同时变化。
- 导航与术语测试不再出现“家庭总览”“按房间查看”或场地 Tab。
- 搜索组件测试断言首页和搜索页共享相同外壳样式。
- Playwright 在桌面、iPhone、Pixel 验证场地切换、移动布局和搜索提交。
