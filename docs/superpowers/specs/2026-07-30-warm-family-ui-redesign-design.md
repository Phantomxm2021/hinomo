# Nomo「温暖家庭」界面重设计规范

日期：2026-07-30

状态：待最终审阅

适用范围：React Web/PWA，桌面与移动端
业务基础：`docs/QR_Code_智能收纳清单管理系统_PRD.md`

## 1. 设计目标

Nomo 是面向家庭用户的二维码收纳工具。界面需要优先解决三个问题：

1. 用户第一次打开就知道如何扫码、搜索和查看箱子。
2. 信息结构符合家庭用户的空间记忆：空间 → 箱子 → 物品。
3. 移动端可单手完成扫码、查看和录入；桌面端适合管理与批量打印。

本次重设计不改变 Supabase 数据模型、R2 媒体链路或现有公开/私有权限规则。

## 2. 已确认的设计方向

采用 A「温暖家庭」方向：暖中性色背景、陶土橙主色、圆润但克制的组件、适量图片和清晰的位置描述。产品气质应接近可靠的家庭生活工具，而不是企业库存后台或纯展示型生活方式应用。

核心原则：

- 扫码、搜索和新增是明确动作，使用按钮或输入控件，不伪装成信息卡片。
- 卡片只用于承载空间、箱子等可浏览对象。
- 物品清单与搜索结果使用紧凑列表，避免所有内容都卡片化。
- 优先展示用户能理解的名称和位置，系统编号作为次级信息。
- 移动端与桌面端保持同一视觉语言，但不强求相同布局。

## 3. 信息架构与导航

### 3.1 业务层级

```text
用户
└── 空间（客厅、卧室、书房等）
    └── 箱子
        └── 物品
```

空间是一级浏览入口。用户既可以沿层级查找，也可以通过搜索或扫码跳过层级直接到达目标。

### 3.2 移动端导航

底部固定五入口：

1. 首页
2. 空间
3. 扫码
4. 箱子
5. 搜索

扫码使用 A3 方案：位于底部导航中央，视觉上抬高，使用二维码/扫描图标并保留“扫码”文字。扫码入口在主要登录页面持续可见，不在首页内容区重复放置大型扫码卡片。

底部导航需要避让 iOS/Android 安全区；页面正文底部留出导航高度加安全区的滚动空间。

### 3.3 桌面端导航

左侧固定导航：

- 今日收纳
- 我的空间
- 全部箱子
- 查找物品
- 打印标签

侧栏只放页面导航，不放扫码动作。扫码与搜索组成桌面工具栏：搜索框右侧放置 44–46px 的陶土橙图标按钮，只显示扫描图标。

图标按钮必须具备：

- `aria-label="扫码查看"`
- 悬停提示“扫码查看”
- 明显的键盘焦点环
- Enter/Space 触发

## 4. 页面设计

### 4.1 首页

首页回答“今天找什么”，不承担完整管理功能。

移动端顺序：

1. 品牌与用户入口
2. 问候语
3. 搜索框
4. 房间快捷筛选
5. 最近打开的箱子列表
6. A3 底部导航与中央扫码按钮

桌面端顺序：

1. 问候语与搜索/扫码工具栏
2. 空间、箱子、物品三个概览数字
3. 按房间查看
4. 最近打开的箱子

首页不展示公开/私有统计详情；权限状态应在具体箱子和管理列表中呈现。

### 4.2 空间页

空间页使用房间卡片。每张卡片展示：

- 空间名称
- 可选位置说明
- 箱子数量
- 物品总数
- 房间类型图标或柔和色块

点击空间进入该空间的箱子列表。新增空间使用明确的加号按钮；空状态提供“创建第一个空间”。

### 4.3 箱子列表

移动端默认使用双列图片网格，顶部提供按空间筛选。每个箱子展示：

- 封面图或稳定占位图
- 箱子名称
- 所属空间
- 次级箱子编号

桌面端根据可用宽度使用三至四列网格，并提供列表/网格切换的扩展位置，但第一轮只实现网格视图。

创建箱子使用明确的“新增”按钮。公开/私有状态使用文字标签，不只依赖颜色。

### 4.4 箱子详情

扫码后的落地页首先说明“这是哪个箱子、放在哪里、里面有什么”。

页面内容：

1. 箱子封面、编号和权限状态
2. 箱子名称
3. 空间、具体位置、物品合计、最近更新时间
4. 物品列表
5. 编辑、打印和新增物品操作

移动端的“添加物品”按钮固定在全局导航上方的底部拇指区，两者之间至少保留 8px 间距，并共同避让系统安全区。匿名查看公开箱子时不显示编辑和新增操作；私有箱子继续遵循现有授权规则。

### 4.5 新增/编辑物品

录入顺序：

1. 拍照或选择图片（可选）
2. 物品名称（必填）
3. 分类（可选）
4. 数量（默认 1，使用步进器）
5. 备注（可选）

保存按钮固定在移动端底部操作区。图片上传与文字保存保持现有可重试语义：图片失败时保留填写内容和已创建记录，并提供独立重试入口。

### 4.6 搜索页

搜索结果优先回答“东西在哪里”。每条物品结果展示：

- 物品名称和图片/占位图
- 数量
- 空间名称
- 所属箱子
- 可选分类

结果使用紧凑列表，不使用大卡片。物品结果和箱子结果分组；无结果时提供修改关键词和扫码查找的建议。

### 4.7 二维码打印

桌面端提供批量打印工作台：左侧/主体选择箱子，右侧实时展示 A4 标签预览，主操作为“下载 PDF”。

移动端只提供单个箱子的二维码下载或系统分享，不复制桌面端复杂批量工作台。

## 5. 视觉系统

### 5.1 色彩

建议基础变量：

| 用途 | 建议值 | 说明 |
|---|---:|---|
| 页面背景 | `#F8F2E8` | 暖米色，降低后台工具感 |
| 主表面 | `#FFFDF8` | 卡片、输入和导航 |
| 侧栏背景 | `#F0E3D3` | 桌面导航层级 |
| 主文字 | `#30271E` | 高对比暖黑 |
| 次级文字 | `#756A5E` | 位置、说明、时间 |
| 主操作 | `#DF6538` | 扫码、新增、保存 |
| 成功/自然辅助 | `#71896F` | 成功状态和空间辅助色 |
| 危险 | `#B42318` | 删除和不可逆操作 |

不能只用颜色表达公开/私有、成功/失败或选中状态。

### 5.2 字体与层级

使用系统无衬线字体栈，避免额外字体请求。中文正文以 15–16px 为基准；移动端页面标题 24–28px；桌面主标题 28–36px。大标题只用于首页问候，不在管理页面重复使用超大字号。

### 5.3 圆角、间距与阴影

- 输入与普通按钮：12–15px 圆角
- 对象卡片：16–20px 圆角
- 主容器与移动底部导航：20–24px 圆角
- 采用 4/8px 间距体系
- 阴影只用于浮层、底部导航和主动作；普通卡片优先用浅边框区分

### 5.4 图标与图片

实现时使用一致的 SVG 图标库，不使用字符符号或 Emoji 作为正式界面图标。效果图中的 Emoji 仅用于表示空间和物品图像位置。

用户未上传图片时使用按对象类型区分的柔和色块与统一占位图，不生成假照片。

## 6. 响应式规则

- 移动基准宽度：320–767px
- 平板：768–1023px
- 桌面：1024px 及以上
- 主内容最大宽度约 1200–1280px
- 移动端单列；箱子列表在足够宽时双列
- 桌面端使用固定侧栏与弹性内容区
- 平板优先保留移动导航，避免过早切换为拥挤侧栏

布局由容器宽度决定，不依赖设备型号。触控目标最小 44×44px。

## 7. 状态与错误处理

所有数据页必须定义：

- 骨架或轻量加载状态
- 空状态及明确下一步
- 局部加载失败与重试
- 删除二次确认
- 保存进行中与防重复提交
- 离线或网络中断提示

媒体错误不显示完整预签名 URL。可显示安全的阶段、HTTP 状态和服务错误码，但不得记录签名参数、Access Key ID 或对象授权信息。

## 8. 组件边界

建议拆分：

- `AppShell`：桌面侧栏、移动底部导航、安全区
- `GlobalFindBar`：桌面搜索框与扫码图标按钮
- `MobilePrimaryNav`：五入口导航与中央扫码按钮
- `SpaceCard`：空间概览
- `BoxCard`：箱子网格单元
- `ItemRow`：物品与搜索结果行
- `BoxHero`：箱子详情头部
- `StickyPrimaryAction`：移动底部新增/保存操作
- `MediaField`：图片选择、压缩、上传状态与重试
- `PrintWorkspace`：选择列表与 A4 预览

页面负责组合与数据查询，组件负责展示和局部交互；不在视觉组件中直接访问 Supabase。

## 9. 无障碍与交互

- 所有图标按钮提供可访问名称和工具提示
- 焦点顺序与视觉顺序一致
- 支持键盘完成搜索、扫码触发、表单和打印选择
- 文本与背景达到 WCAG AA 对比度
- 支持 `prefers-reduced-motion`
- 表单错误靠近字段展示，并使用 `aria-describedby`
- 底部固定操作不得遮挡内容或系统安全区

## 10. 验收标准

### 移动端

- 在首页任意滚动位置可通过中央按钮进入扫码
- 底部导航包含首页、空间、扫码、箱子、搜索五个明确入口
- 320px 宽度无水平滚动
- 新增物品可单手完成，主要按钮不被导航遮挡
- 公开箱子匿名可读，编辑操作仅登录用户可见

### 桌面端

- 扫码图标位于搜索框右侧，侧栏无扫码动作
- 扫码按钮具备工具提示、可访问名称和键盘操作
- 空间、箱子和最近使用内容在 1024px 宽度保持清晰层级
- 批量打印同时提供选择状态和 A4 预览

### 质量

- 既有 Supabase/R2 数据流和权限规则不回归
- 关键页面具有组件测试和三设备 E2E 覆盖
- Chrome、Safari 移动端和 Chromium 桌面完成视觉检查
- 生产构建通过，且新增视觉资源不显著增加首屏体积

## 11. 实施边界

本轮实施包括现有页面的布局与视觉重构、导航调整和组件拆分。暂不包括家庭成员协作、AI 图片识别、NFC、复杂库存统计、动态主题编辑器或新的后端表结构。

建议按“视觉基础与壳层 → 首页/空间/箱子 → 箱子详情/物品表单 → 搜索/打印 → 响应式与回归验证”的顺序实施。
