# 桌面端语言入口与设置弹窗设计

日期：2026-08-08

## 目标

- 桌面端不在侧栏品牌区或账户区重复展示语言选择器。
- 语言选择器只保留在“设置 → 通用设置”中，作为全局 `zh-CN / en-US` 状态的唯一显式入口。
- 桌面端进入设置时使用居中弹窗，不再把设置内容当作普通页面铺开。
- 移动端保持现有设置页面层级和底部导航行为，不因为桌面改动增加额外入口。

## 交互设计

### 语言入口

`AppShell` 桌面侧栏移除 `LanguageSwitcher`。用户从账户菜单进入设置，再进入通用设置，在通用设置弹窗/页面中切换语言。语言切换仍由全局 `I18nProvider` 管理，并继续同步已登录用户的 profile locale；不再添加第二个可见选择器。

### 桌面设置

保留 `/app/me/settings` 与 `/app/me/settings/general` 路由，以支持刷新、深链接和浏览器返回。桌面视口下：

- 设置内容通过现有 `ResponsiveEditorDialog` 渲染为居中弹窗和遮罩层。
- 弹窗标题、关闭按钮、焦点恢复和 `aria-modal` 遵循现有对话框规范。
- 设置列表中的“通用”继续进入 `/app/me/settings/general`，并以同样的弹窗容器展示语言设置。
- 关闭弹窗或点击返回时回到进入设置前的页面，不改变语言状态。

### 移动设置

移动视口下继续使用现有页面式设置层级和返回导航。通用设置页保留语言选择器，使用现有底部抽屉/页面交互，不在 AppShell 或账户菜单增加语言控件。

## 实现边界

- 抽取可复用的设置内容组件，避免桌面弹窗和移动页面复制文案与表单逻辑。
- 为 `ResponsiveEditorDialog` 增加设置场景需要的桌面/移动显示能力时，保持现有箱子、物品等调用方行为不变。
- 不改变认证、profile locale RPC、路由路径、数据库结构或语言字典契约。
- 不处理与本需求无关的导航、设置项或视觉主题重构。

## 验收与测试

- `AppShell` 桌面渲染不再出现语言选择器；账户菜单的设置入口仍可用。
- `/app/me/settings` 桌面渲染为 `role="dialog"` 的居中弹窗，具有遮罩、标题和关闭行为。
- `/app/me/settings/general` 桌面同样为弹窗，且只出现一个语言选择器。
- 移动视口保持页面式设置和一个语言选择器，不出现额外侧栏入口。
- 关闭弹窗后焦点回到账户菜单设置入口或触发入口，浏览器返回行为保持可用。
- 既有全局 i18n、AppShell、SettingsPage、GeneralSettingsPage 与 ResponsiveEditorDialog 测试继续通过。
