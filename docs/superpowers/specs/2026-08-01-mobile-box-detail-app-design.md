# 移动端箱子详情 App 化设计

## 目标

将箱子详情页在小于 `lg` 的视口重构为接近原生移动 App 的信息与操作结构，同时保持桌面端现有布局、视觉和功能不变。

## 设计原则

- 移动端去除外层 Web 卡片、显式边框和虚线空状态容器。
- 使用紧凑页面边距、分组信息、连续列表和安全区底部操作。
- 内容层级依次为封面、身份信息、辅助信息、所有者操作、箱内物品。
- 保留现有数据、权限、编辑、删除、打印及新增物品行为，不改变 API。
- 桌面端继续使用现有双栏详情卡、按钮和物品卡片，并通过 `lg:` 响应式样式隔离。

## 移动端结构

### 封面与身份信息

- 封面使用接近全宽的 4:3 图片，保留圆角，不再放在外层卡片内。
- 箱子编号作为品牌色小型辅助标签。
- 箱子名称作为页面主标题。
- 可见性与更新时间使用弱化的单行元信息，不使用带外框的 Web 标签。

### 详情信息

- 位置、备注和数量统计组成紧凑的信息分组。
- 位置与备注使用自然文本层级；无内容时继续显示现有占位文案。
- 数量统计保留“件数 + 种类”的业务表达。

### 所有者操作

- 编辑与打印组成横向双操作栏，使用 App 风格填充背景与按压反馈。
- 桌面端“新增物品”按钮保持原位置；移动端继续使用底部固定主按钮。

### 物品清单

- 标题与种类数量位于同一行。
- 物品改为连续分组列表：缩略图、名称/分类/描述、数量和操作形成紧凑行。
- 项目之间使用轻量分隔，而不是每项一个独立 Web 卡片。
- 空状态为无外框的居中文案和图标，不增加创建按钮。

## 加载、错误与表单

- 移动端 Skeleton 与最终页面结构一致，避免加载完成后明显跳动。
- 保留现有响应式错误提示和重试行为。
- 新增/编辑物品表单、确认删除和焦点恢复逻辑保持不变。

## 验证标准

- 移动端不再出现详情外层 Web 卡片或物品虚线空卡片。
- 移动端物品使用连续列表，底部新增按钮继续遵守安全区。
- 桌面端仍具有双栏详情卡、边框和物品独立卡片。
- 匿名访问、所有者操作、打印、编辑、删除、新增及焦点恢复测试继续通过。
- TypeScript、Lint、单元测试、生产构建与移动/桌面 E2E 通过。
