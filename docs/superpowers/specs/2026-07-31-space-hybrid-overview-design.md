# Nomo 空间页混合总览设计

日期：2026-07-31

状态：已确认，采用 B「卡片 + 轻量 2D 家庭总览」

## 1. 目标

空间页同时服务两类任务：

1. 高频任务：快速查看空间统计并进入该空间的箱子列表。
2. 空间记忆任务：通过房间之间的相对位置回忆物品大致位于家中哪里。

默认视图必须保持高效、可扫描；2D 总览是可选增强层，不得要求用户先完成建模。

## 2. 研究结论与方案取舍

- 卡片适合承载单一空间对象，能够建立清晰内容层级和明确入口。
- 2D 空间关系可以补充“房间之间在哪里”的记忆线索。
- 3D 在复杂空间决策中可能有价值，但会增加视觉搜索、操作学习、设备性能和数据录入成本。
- 当前业务数据没有墙体、尺寸、坐标、楼层模型或扫描结果，因此不采用 CAD、3D 或 AR 作为空间页主界面。

## 3. 页面结构

### 3.1 页面标题区

- 标题：空间。
- 说明：整理你的收纳范围。
- 主操作：创建空间。
- 视图切换：卡片 / 平面。
- 视图偏好保存在浏览器本地；首次进入默认卡片视图。

### 3.2 卡片视图

每张空间卡包含：

- 根据空间名称匹配的生活化图形；未知名称使用家庭图形。
- 空间名称和可选描述。
- 箱子数量和物品数量，数字优先展示。
- 点击主体进入该空间的箱子列表。
- 编辑和删除作为次级图标操作，位于卡片底部操作区。

响应式规则：移动端单列，较宽移动端与平板双列，宽桌面三列。

### 3.3 轻量 2D 平面视图

- 使用暖色网格画布表达家庭范围，不绘制真实墙体。
- 每个空间是一个可聚焦的房间块，显示图形、名称、箱子数和物品数。
- 点击房间块进入筛选后的箱子列表。
- 编辑布局模式下，可拖动房间块；键盘方向键每次移动 2%。
- 坐标以画布百分比保存，并以 2% 网格吸附。
- 初次使用或缺少记录时按稳定顺序自动排布。
- 移动端保留平面浏览；拖动操作只在用户开启编辑布局后生效。
- 保存失败显示局部提示，当前页面位置不回滚；用户可以重试拖动。

## 4. 数据模型

新增 `public.space_layouts`：

- `space_id uuid primary key`，级联关联 `public.spaces(id)`。
- `owner_id uuid not null`，关联 `auth.users(id)`。
- `x_percent smallint`，范围 0–80。
- `y_percent smallint`，范围 0–90；仍由纵向总边界约束保证房间不超出画布。
- `width_percent smallint`，范围 20–60，第一阶段固定使用默认值。
- `height_percent smallint`，范围 10–50，第一阶段由双列自动布局稳定生成。
- `created_at`、`updated_at`。

RLS 仅允许空间所有者读取、插入和更新。删除空间时布局记录自动级联删除。

前端单独查询布局表；如果迁移尚未执行或没有记录，空间卡片和自动平面布局仍正常工作。保存布局需要用户先执行迁移 SQL。

## 5. 组件边界

- `SpacesPage`：数据查询、创建/编辑/删除、视图切换和错误状态。
- `SpaceCard`：空间卡片的展示与次级操作。
- `SpaceMap`：自动布局、绝对定位、拖动、键盘移动和保存回调。
- `spaces.api.ts`：空间读写与布局读写。

`SpaceMap` 不直接访问 Supabase，以便单独测试交互和布局计算。

## 6. 无障碍

- 视图切换使用带选中状态的按钮组。
- 房间块是可聚焦链接；布局编辑状态通过说明文字和 `aria-pressed` 表达。
- 键盘用户可使用方向键移动房间块。
- 不只用颜色表达空间身份或编辑状态。
- 触控目标至少 44px。
- `prefers-reduced-motion` 下不使用位置过渡。

## 7. 验收标准

- 卡片视图是首次和默认视图。
- 卡片与平面视图均能进入正确的空间筛选箱子列表。
- 有 1–12 个空间时自动布局稳定且不超出画布。
- 拖动和键盘移动保存相同的百分比坐标。
- 320px 宽度无页面级横向滚动。
- 布局 API 不可用时卡片视图和自动平面视图仍可用。
- 既有创建、编辑、删除阻止、弹窗隔离和焦点恢复行为不回归。

## 8. 非目标

- 精确 CAD 绘制。
- 楼层、墙体、门窗和真实尺寸。
- 3D、WebGL、AR 或摄像头扫描。
- 多人协同编辑布局。
- 房间块自由缩放。
