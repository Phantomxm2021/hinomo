# Nomo 现代化“全部箱子”目录设计

日期：2026-07-31

状态：已确认

## 1. 目标

将“全部箱子”页面从操作按钮密集的大图卡片集合，升级为以“快速找到并打开箱子”为首要任务的轻量目录。

本次采用已确认的 A 方案：搜索优先、整卡打开、管理操作降级、桌面与移动端保持一致的信息顺序和交互模型。

## 2. 设计原则

- **查找优先**：用户进入页面后先看到搜索和空间筛选，而不是管理按钮。
- **整卡打开**：卡片主体是唯一主要动作，点击后进入现有箱子详情页。
- **管理降级**：编辑与删除收纳在右上角更多菜单中，避免每张卡片重复展示三个按钮。
- **信息克制**：每张卡片只展示识别和定位箱子所需的信息。
- **响应式一致**：移动端和桌面端不改变交互含义，只调整密度与文字长度。
- **延续设计语言**：沿用暖色令牌、圆角、字体层级和 44px 最小触控目标。

## 3. 页面信息架构

页面按以下顺序排列：

1. 标题区
2. 搜索与排序工具栏
3. 空间筛选
4. 结果状态或箱子目录
5. 创建箱子模态与删除确认框

### 3.1 标题区

- 眉题：`收纳目录`
- 主标题：`全部箱子`
- 摘要：`{箱子数} 个箱子 · {物品总数} 件物品`
- 主操作：桌面显示“创建箱子”，移动端显示“新建”；继续打开现有 URL 驱动的创建模态。
- “批量打印”不再占用标题区，现有侧栏“打印标签”承担入口职责。

### 3.2 搜索与排序

- 页面内搜索范围：箱子名称、箱子编号、空间名称和具体位置。
- 搜索使用受控输入，查询字符串写入 URL 的 `q` 参数，刷新和分享后可恢复。
- 匹配忽略大小写并裁剪首尾空格。
- 默认排序为“最近更新”。
- 排序选项：最近更新、名称 A–Z、物品数量从多到少。
- 排序状态写入 URL 的 `sort` 参数；默认值不写入 URL。
- 本轮使用现有已加载箱子数据在客户端完成搜索、筛选和排序，不新增 Supabase 查询或数据库索引。

### 3.3 空间筛选

- 保留 `space` URL 参数和现有唯一空间集合。
- 筛选项显示“空间名称 + 当前总箱子数”。
- “全部空间”显示全部结果。
- 移动端横向滚动，不换行，不造成页面级横向溢出。
- 搜索、空间和排序组合生效；修改其中一个条件不清除其他条件。

## 4. 箱子卡片

### 4.1 布局

- 容器最大宽度继续遵循现有工作区。
- 320–419px：单列，保证可读性和触控安全。
- 420px 至桌面导航断点前：双列。
- 桌面：三列；宽屏：四列。
- 封面采用较紧凑的 `16:10` 比例，减少纵向占用。

### 4.2 信息层级

卡片依次展示：

1. 封面图或稳定占位图
2. 公开/私有文字徽标
3. 箱子名称
4. `空间名称 · 具体位置`
5. 物品数量和箱子编号

位置为空时显示“未填写位置”。公开状态继续同时使用图标和文字，不只依赖颜色。

### 4.3 交互

- 卡片主体使用可访问链接，进入 `/b/:publicId`。
- 鼠标悬停时轻微上移并加强边框/阴影；键盘焦点使用现有全局焦点环。
- 右上角更多按钮独立于卡片链接，具有 `aria-label="管理{箱子名}"`。
- 更多菜单包含“编辑箱子”和“删除箱子”。
- 点击菜单外、按 Escape 或执行操作后关闭菜单。
- 删除继续使用现有 `ConfirmDialog`；不增加内联危险操作。
- 同一时间只允许一个卡片菜单打开。

## 5. 状态与反馈

### 5.1 加载和错误

- 保留现有 `PageState` 加载与获取失败重试。
- 删除失败在目录上方使用 `role="alert"`，并保留当前筛选、搜索和菜单上下文。

### 5.2 空状态

- 数据库没有任何箱子：展示“还没有箱子”和创建入口。
- 有箱子但组合条件无结果：展示“没有匹配的箱子”，提供“清除筛选”按钮；不显示创建引导，避免误导用户。
- 清除筛选仅移除 `q`、`space` 和 `sort`，保留 `create` 等非目录参数。

### 5.3 创建和删除后的同步

- 创建完成继续使 `['boxes']` 查询失效并关闭模态。
- 删除成功后使 `['boxes']` 查询失效；若当前空间因此无结果，显示组合条件空状态。
- 现有创建期间导航阻止、焦点恢复、R2 上传和二维码结果不变。

## 6. 组件边界

- `BoxesPage`：负责查询、URL 状态组合、结果统计和页面编排。
- `BoxCatalogueToolbar`：负责搜索输入、排序和清除行为，不读取 Supabase。
- `SpaceFilterChips`：负责空间筛选渲染和计数。
- `BoxCatalogueCard`：负责单张卡片、主链接和更多菜单触发。
- `BoxCardMenu`：负责编辑/删除菜单、点击外部与 Escape 关闭。
- `CreateBoxModal` 与 `ConfirmDialog`：保持现有职责。

组件通过明确 props 传递数据和事件，不引入全局目录状态库。

## 7. 数据流

1. `listBoxes()` 获取当前用户全部箱子，继续按 `updated_at` 降序返回。
2. 页面从 URL 读取 `q`、`space`、`sort`、`create`。
3. 客户端按搜索文本和空间筛选箱子。
4. 对筛选结果应用排序。
5. 标题摘要使用全部箱子总数和全部物品总数；结果区显示当前结果数量。
6. 用户更改搜索、空间或排序时使用 `replace` 更新 URL，避免每个输入字符污染浏览器历史。
7. 用户打开创建模态时继续使用历史栈，使浏览器后退可关闭模态。

## 8. 无障碍与响应式

- 搜索框有可见标签或 `aria-label="搜索箱子"`。
- 排序控件有 `aria-label="箱子排序"`。
- 空间按钮使用 `aria-pressed`。
- 卡片主链接名称包含箱子名称；更多按钮和删除按钮包含具体箱子名称。
- 菜单使用语义化菜单或等价的可访问弹出结构，并管理打开/关闭焦点。
- 所有交互目标最小高度/宽度为 44px。
- 320px 宽度下不发生页面级横向滚动。
- 移动端内容底部继续避让固定导航和安全区。
- 尊重现有 `prefers-reduced-motion` 规则。

## 9. 测试策略

### 9.1 单元与组件测试

- 搜索覆盖名称、编号、空间和位置。
- 搜索、空间筛选和排序可组合，并正确写回 URL。
- 默认排序、名称排序和物品数量排序正确。
- 标题摘要和当前结果数正确。
- 整卡链接进入正确详情地址。
- 更多菜单一次只打开一个，支持 Escape 和点击外部关闭。
- 编辑地址正确，删除仍经过确认框。
- 无数据空状态与无匹配空状态互不混淆。
- 清除筛选保留非目录查询参数。

### 9.2 端到端测试

- 桌面、iPhone 和 Pixel 均能搜索并打开目标箱子。
- 三端均能通过更多菜单进入编辑和触发删除确认。
- URL 状态刷新后可恢复。
- 搜索、筛选后的页面无横向溢出。
- 创建箱子模态流程不回归。

### 9.3 工程验证

- Vitest 全量测试
- TypeScript 类型检查
- Oxlint
- Vite 生产构建
- Playwright 桌面、iPhone、Pixel 项目
- `git diff --check`

## 10. 非目标

- 服务端全文搜索、分页或无限滚动。
- 批量选择、批量删除或批量修改权限。
- 新增列表/网格视图切换。
- 右侧快速预览面板。
- 修改 Supabase 表结构、RLS、R2 协议或二维码格式。
- 重设计箱子详情、编辑页或创建模态。

## 11. 验收标准

- 用户可通过名称、编号、空间或位置快速找到箱子。
- 页面没有重复的查看/编辑/删除按钮组。
- 点击卡片主体直接进入详情；管理操作集中在更多菜单。
- 桌面与移动端视觉层级和操作模型一致。
- 暖色设计令牌、字体层级和导航结构与已确认系统设计一致。
- 搜索、筛选、排序、空状态、删除和创建流程均有自动化覆盖。
- 完整工程验证通过。
