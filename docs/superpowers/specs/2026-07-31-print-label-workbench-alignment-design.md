# Nomo 打印标签工作台设计对齐规格

日期：2026-07-31

状态：视觉方案已确认，等待实施

适用范围：`/app/print` 桌面与移动端

视觉选择：A1「A4 双列清晰型」

## 1. 目标与边界

打印标签页需要与 Nomo「温暖家庭」设计语言保持一致，并让页面预览真实反映最终 PDF，而不是展示一张与打印结果脱节的示意卡片。

本次实现包含：

- 桌面端批量选择、搜索、全选和真实 A4 双列预览。
- 移动端单选、单标签预览和下载。
- 打印进度、二维码预览失败、PDF 生成失败及无箱子状态。
- 现有每页 8 张、两列四行 PDF 排版保持不变。

本次不包含：

- 自定义纸张、列数、边距或字号。
- 标签模板编辑器。
- 系统分享、打印机发现或云端打印。
- Supabase、R2、权限策略或数据库变更。

## 2. 页面信息层级

页面标题区依次展示：

1. Eyebrow：`打印中心`。
2. 页面标题：`打印二维码标签`。
3. 说明：`选择箱子，预览 A4 排版并下载可打印 PDF`。

桌面端标题区右侧显示紧凑摘要：`A4 · 双列 · 已选 N 张`。移动端标题改为 `下载箱子标签`，说明为 `移动设备每次处理一张标签`。

管理页面不使用首页级超大标题。标题、正文和元信息沿用现有 Tailwind 设计 token。

## 3. 桌面端布局

`lg` 及以上使用两栏工作台：

- 页面内容最大宽度沿用 AppShell 的主内容约束。
- 两栏间距 24px。
- 左栏宽度约 340–360px，承载选择和下载操作。
- 右栏占据剩余宽度，承载 A4 预览。

### 3.1 左栏：箱子选择

左栏使用一个完整表面卡片，不把每个箱子做成独立大卡片。

结构：

1. 标题 `选择箱子` 与 `N 已选` 状态徽标。
2. 搜索框，支持箱子名称、编号、空间和位置；只影响当前可见列表。
3. `共 N 个箱子` 与 `全选`/`取消全选`。全选只作用于当前搜索结果，保留未显示项的已有选择。
4. 可滚动紧凑选择列表。每行展示复选框、名称、空间与位置、次级编号。
5. 底部主按钮 `下载 PDF`。未选择箱子或正在生成时禁用。

选中行使用浅陶土色表面和品牌色边框。行高与触控目标不低于 44px。复选框保留原生语义和键盘操作。

### 3.2 右栏：真实 A4 预览

预览卡片顶部显示 `A4 标签预览` 和 `共 N 页 · N 张标签`。

预览舞台使用比页面背景略深的暖灰米色。纸张：

- 固定 `210 / 297` A4 宽高比。
- 白色纸张、轻微投影，不使用厚重卡片边框。
- 每页两列四行，共 8 张。
- 标签顺序与左栏选择列表和最终 PDF 输入顺序一致。
- 超过 8 张时纵向排列多页，预览区域自身滚动。

每张标签展示：

- 实际公开访问 URL 对应的二维码。
- 箱子名称。
- 箱子编号。
- 空间与具体位置。
- `扫码查看箱内物品`。

预览的比例、间距、字段顺序、配色和 PDF 标签保持同源。CSS 负责屏幕缩放，PDF 仍由现有 Canvas/jsPDF 链路生成。

未选择箱子时，右栏保留空纸张轮廓，并显示 `选择箱子后将在这里生成 A4 预览`，不显示无关插画。

## 4. 移动端布局

小于 `lg` 时不复制桌面批量工作台：

1. 单选箱子列表，使用原生 radio。
2. 选中后展示一张完整标签预览，字段与 PDF 标签一致。
3. 主按钮 `下载单个标签`，宽度占满内容区，保持 48px 最小高度。
4. 页面底部空间继续避让 AppShell 移动导航和安全区。

移动端不显示桌面多选框、全选、A4 多页纸张或桌面下载按钮。二维码生成中显示稳定占位；失败时在预览位置给出可理解的失败说明，按钮仍可尝试生成 PDF。

## 5. 视觉语言

沿用已确认的设计 token：

- 页面背景：`canvas` / `#F8F2E8`。
- 表面：`surface` / `#FFFDF8`。
- 主文字：`ink` / `#30271E`。
- 次级文字：`muted` / `#756A5E`。
- 主操作：`brand` / `#DF6538`。
- 边框：`line` / `#E3D5C5`。

普通卡片只用细边框分层；阴影仅用于 A4 纸张和必要浮层。控件圆角使用 `rounded-control`，工作台容器使用 `rounded-card`。不引入新的颜色系统、Emoji 或字符图标。

## 6. 组件与数据流

`PrintPage` 继续负责页面查询、选择、搜索、生成状态和 PDF 调用。为避免单个组件继续膨胀，视图拆分为两个局部职责组件：

- `PrintBoxSelector`：搜索、全选、选择列表和下载按钮。
- `PrintSheetPreview`：将选中箱子分页，并渲染 A4 纸张与标签。

二维码预览使用 `boxQrUrl` 与 `boxQrPng`，与 PDF 使用相同目标 URL。预览二维码按箱子 ID 缓存；选择变化时只生成缺失项。异步结果必须携带箱子 ID，不能把旧二维码配到新元数据。组件卸载后不得写入状态。

数据流：

```text
listBoxes
   ↓
搜索后的可见箱子 ──→ 全选/取消全选
   ↓                       ↓
selected ids ───────→ selected boxes
                         ├──→ A4 分页预览 + QR 缓存
                         └──→ buildLabels → renderLabelsPdf
```

## 7. 状态与错误处理

- 初始加载：使用现有 `PageState`。
- 初始查询失败：阻断式错误状态与重试。
- 无箱子：解释需要先创建箱子，并提供跳转到箱子页的操作。
- 无选择：选择列表可用，预览为空纸张，下载按钮禁用。
- 二维码预览生成中：每个标签显示局部占位，不阻塞其它标签。
- 单个二维码预览失败：只标记对应标签，不能清空其它成功预览。
- PDF 生成中：按钮显示 `生成中…`、禁用重复提交，并展示 `completed / total` 进度。
- PDF 失败：保留选择和预览，显示 `PDF 生成失败，请重试`。

## 8. 可访问性

- 工作台、选择区、A4 预览和移动单标签区使用有名称的 region。
- 搜索框有明确 label 或 `aria-label`。
- 选择数量和渲染进度使用 `role="status"`，错误使用 `role="alert"`。
- 全选是 `<button>`，支持键盘与清晰焦点环。
- 选择行点击区域与原生 input 关联，不用纯视觉元素模拟选中。
- A4 预览中的二维码图片带箱子名称上下文；装饰性纸张容器不重复朗读全部信息。
- 生成期间不把焦点强制移走；失败后用户可直接重试。

## 9. 测试与验收

### 9.1 单元/组件测试

- 搜索覆盖名称、编号、空间、位置。
- 全选只选择当前搜索结果，取消全选不误删隐藏选择。
- 多选生成与 A4 预览使用相同顺序。
- 9 张标签分页为 8 + 1，页面摘要正确。
- 异步二维码不会发生旧图与新元数据错配。
- 单个二维码失败不影响其它预览。
- 桌面多选和移动单选保持隔离。
- 加载、查询失败、无箱子、无选择、生成中、进度和 PDF 失败均有语义断言。

### 9.2 响应式与浏览器验收

- 桌面 1440×900：两栏工作台完整可见，A4 纸张比例正确，无页面级横向滚动。
- 桌面 1024×768：左栏保持可操作，右栏纸张缩放而不溢出。
- 平板 768×1024：使用移动单标签流程。
- 手机 390×844、360×800、320×568：单选、预览、下载按钮和底部导航互不遮挡。
- 键盘可完成搜索、选择、全选和下载。

### 9.3 回归门禁

- PrintPage 与 PDF 聚焦测试。
- 全量 Vitest、typecheck、lint、生产构建。
- Playwright desktop、iPhone、Pixel。
- `git diff --check` 与工作树审计。

## 10. 成功标准

打印标签页在视觉上与已确认效果一致；桌面预览真实表达最终 A4 双列四行排版，移动端提供明确的单标签预览与下载路径。用户能在不理解 PDF 技术细节的情况下完成选择、确认和下载，且所有既有权限与生成能力保持不变。
