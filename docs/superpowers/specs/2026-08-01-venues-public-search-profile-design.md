# 场地、公开访问、移动搜索与“我的”设计规格

## 目标

在不引入 Edge Function 的前提下，完成四类能力：修复匿名访问公开箱子、让移动搜索具有明确可靠的触发方式、让空间平面图支持调整卡片尺寸、增加“场地 → 空间”层级，并为移动端提供独立“我的”页面。

## 已确认的信息架构

系统层级调整为：

`用户 → 场地 → 空间 → 箱子 → 物品`

- 一个用户可以拥有多个场地，例如“家里”“公司”。
- 一个空间必须且只能属于一个场地。
- 一个箱子仍属于一个空间，不直接关联场地。
- 现有空间迁移到自动创建的默认场地“家里”。
- 搜索和箱子展示位置时使用“场地 · 空间 · 位置”，避免不同场地下的同名空间混淆。

移动端底部导航保持五项：

`首页 · 场地/空间 · 扫码 · 箱子 · 我的`

原“搜索”Tab 被“我的”替换；首页搜索仍是全局搜索主入口。

## 阶段一：现有缺陷修复

### 公开箱子匿名访问

#### 根因

当前公开箱子查询从 `boxes` 嵌套读取 `spaces(name)`。匿名角色虽可读取公开 `boxes` 和对应 `items`，却无权读取 `spaces`，因此 PostgREST 会让整条嵌套查询失败，页面只能显示“无权限或内容不存在”。真实匿名浏览器已稳定复现。

#### 方案

新增 `public.get_public_box(p_public_id uuid)` RPC：

- 使用 `security definer`，固定安全的 `search_path`。
- 只有目标箱子 `visibility = 'public'` 时才返回数据。
- 仅返回公开页需要的箱子字段、所属空间名称和物品数组。
- 不开放匿名用户直接查询 `spaces` 表，也不泄露场地、空间描述或 owner 的其他数据。
- 私密箱子和不存在的 ID 都返回空结果，维持不可枚举语义。
- 授予 `anon` 与 `authenticated` 执行权限。
- 前端匿名或非 owner 访问使用该 RPC；owner 查看自己的私密箱子仍走受 RLS 保护的 owner 查询。

迁移只生成 SQL 文件，由用户自行在 Supabase 执行；Codex 不直接修改数据库。

### 移动搜索触发

#### 根因

搜索结果页有 250ms 自动搜索，但首页 `GlobalFindBar` 只监听表单提交。移动端没有可见提交按钮，也没有 `enterKeyHint="search"`，仅结束输入不会导航，造成“输入了但没有搜索”的感知和真实行为差异。

#### 方案

- 首页搜索框右侧增加可见的搜索图标按钮，44px 以上触控面积。
- 表单输入增加 `enterKeyHint="search"`、正确的 `name` 与自动完成语义。
- 点击按钮或移动键盘“搜索/回车”都导航到 `/app/search?q=...`。
- 搜索结果页改为语义化 `<form role="search">`，保留 250ms 自动搜索，同时支持显式提交。
- 输入法组合期间不触发提交；组合结束后自动搜索。
- 空白关键词不导航、不请求。
- 移动 E2E 覆盖首页输入、按钮提交、Enter 提交和结果展示。

## 阶段二：场地与平面图增强

### 数据模型

新增 `venues` 表：

- `id uuid primary key`
- `owner_id uuid not null references auth.users(id)`
- `name text not null`，同一用户内不区分大小写唯一
- `description text null`
- `created_at`、`updated_at`

`spaces` 增加非空 `venue_id` 外键。迁移过程：

1. 为每个已有空间 owner 创建一个“家里”场地。
2. 将该 owner 的现有空间关联到默认场地。
3. 设置 `venue_id not null`。
4. 新增 RLS：用户只能管理自己的场地；空间写入时场地必须属于同一用户。
5. 更新浏览器 API 列授权、数据库类型和测试 SQL。

删除非空场地时禁止删除，并提示先移动或删除其空间；空场地可确认后删除。

### 场地 UI

- 空间页标题文案升级为“场地与空间”。
- 顶部使用横向可滚动场地 chips，包含“全部”和每个场地的空间数量。
- 提供紧凑的“新增场地”图标操作；创建/编辑使用现有模态窗口设计语言。
- 选中场地后，卡片视图和平面视图只展示该场地的空间。
- 创建空间时必须选择场地，默认选中当前场地。
- 编辑空间可迁移到另一个场地。
- 创建第一个场地后可直接继续创建空间。
- 箱子列表、搜索结果和详情补充 `venue_name`，展示“场地 · 空间 · 位置”。

场地第一版不增加颜色、封面、地址、成员权限或多对多归属，避免超出当前需求。

### 平面图调整大小

现有 `space_layouts` 已持久化 `x/y/width/height` 百分比，因此不新增布局字段。

- “调整布局”模式下，每个空间卡片右下角出现缩放手柄。
- 指针拖动手柄只调整宽高，不触发卡片移动或页面跳转。
- 支持触摸和鼠标 Pointer Events，并使用 pointer capture。
- 宽度限制为 20–60%，高度限制为 10–50%，同时不能越过画布右侧和底部。
- 继续以 2% 网格吸附，释放指针时保存一次，拖动中只更新本地预览。
- 手柄可获得键盘焦点；方向键以 2% 调整尺寸，并通过可访问名称说明操作。
- Escape 取消本轮尺寸调整并恢复初始值。
- 移动卡片与调整尺寸使用不同状态，不能同时发生。
- 保存失败保留本地视觉状态并显示可重试提示；后续成功保存清除错误。

## 阶段三：移动端“我的”

新增 `/app/me` 页面，复用现有 profile API 和头像压缩上传逻辑：

- 显示头像、昵称和邮箱。
- 头像可点击更换；昵称和邮箱只读。
- 设置区提供语言选择，保存状态和错误反馈与桌面账户设置一致。
- 提供明确的退出登录按钮和确认提示。
- 加载期间使用结构化 Skeleton；缓存资料刷新失败时保留旧数据并允许重试。
- 移动端底栏用“我的”替换“搜索”。
- 桌面端继续保留左下角账户菜单，不额外增加侧栏“我的”入口。
- 共用 profile 数据组件，避免桌面弹窗和移动页面出现两套上传、语言或退出逻辑。

## 错误处理与安全

- 公开 RPC 只允许按不可变 `public_id` 获取单个公开箱子；不提供公开列表或模糊搜索。
- 场地、空间、箱子和物品继续由 RLS 按 owner 隔离。
- 场地迁移可重复执行时不产生多个默认场地。
- 前端对“迁移未执行”识别 PostgREST 缺表/缺列错误，显示明确部署提示，不静默降级为错误数据。
- 搜索保留 URL `q` 作为可分享和浏览器前进后退的单一查询来源。
- 所有新增图标按钮均保留 `aria-label`、焦点样式和至少 44px 触控区域。

## 测试与验收

- SQL 测试：匿名只能读取公开箱子 RPC；私密与不存在返回空；场地 RLS 和跨 owner 外键写入被拒绝；默认场地回填正确。
- API 单测：RPC 映射、场地 CRUD、空间 venue 字段、旧 schema 部署提示。
- 组件单测：搜索按钮/Enter/组合输入、场地切换与表单、缩放边界和键盘、我的页面状态。
- E2E：匿名打开公开二维码；匿名无法打开私密二维码；移动首页完成搜索；场地创建并分配空间；平面图移动和缩放保存；“我的”修改头像/语言并退出。
- 视口：320×568、360×800、390×844、768×1024、1024×768、1440×900，无横向溢出或底栏遮挡。

1. 公开 RPC 与移动搜索修复，可独立测试和提交。

3. 场地 UI 与全局位置展示。
4. 平面图尺寸调整。
5. 移动端“我的”与导航调整。
6. 全量浏览器、数据库、单元与 E2E 验证。
