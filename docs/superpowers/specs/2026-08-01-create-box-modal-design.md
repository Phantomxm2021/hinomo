# Nomo 创建箱子模态窗口设计

日期：2026-08-01

状态：已确认

## 1. 目标

将站内“创建箱子”从独立页面跳转改为箱子列表上的模态流程，使用户在创建和查看二维码之后仍保留箱子列表上下文。

编辑已有箱子不在本次范围内，继续使用 `/app/boxes/:boxId/edit` 独立页面。

## 2. 路由与入口

- 创建模态由 `/app/boxes?create=1` 驱动。
- 箱子列表页顶部按钮、空状态按钮和首页“创建第一个箱子”统一进入该地址。
- 原地址 `/app/boxes/new` 重定向至 `/app/boxes?create=1`，兼容旧书签和旧链接。
- 关闭模态时只删除 `create` 参数，保留 `space` 等其他查询参数。
- 浏览器后退可关闭模态；刷新带 `create=1` 的地址后仍打开模态。

## 3. 模态交互

- 桌面端使用居中模态；移动端使用底部全宽弹层。
- 内容区域限制在视口内并独立滚动，避免页面级横向溢出。
- 打开后锁定背景滚动，并通过 `inert` 与 `aria-hidden` 隔离应用背景。
- 自动聚焦第一个可编辑字段，Tab 焦点限制在模态内部。
- 未保存且不处于提交/上传阶段时，可通过关闭按钮、Escape 或点击遮罩关闭。
- 保存或图片上传期间禁止关闭，按钮显示稳定的进行中状态。
- 关闭后焦点恢复到原创建入口；从首页进入时，关闭后停留在箱子列表。

## 4. 表单与成功结果

- 创建表单保留空间、名称、分类、具体位置、备注、封面和查看权限字段。
- 校验、Supabase 创建和 Cloudflare R2 图片上传逻辑沿用现有实现。
- 图片上传失败时保留表单内容和已创建箱子记录，并提供重试上传。
- 创建成功后不立即关闭，模态切换为成功结果：箱号、公开链接、二维码、重新生成和下载 PNG。
- 成功结果提供“完成”按钮；点击后关闭模态并刷新箱子列表。
- 无论公开或私有箱子都生成现有公开地址格式；访问权限仍由现有权限规则控制。

## 5. 组件边界

- `BoxForm`：可复用的创建/编辑表单主体和创建成功结果，不负责路由或背景隔离。
- `CreateBoxModal`：负责模态容器、关闭规则、焦点管理、滚动锁定与完成回调。
- `BoxesPage`：根据 `create=1` 控制模态，关闭时更新查询参数，并在完成后使箱子查询失效。
- `BoxFormPage`：继续承载编辑路由，复用 `BoxForm`；不再作为站内创建入口。
- `/app/boxes/new`：使用重定向组件兼容旧地址。

## 6. 错误处理

- 空间查询失败时在模态内显示可重试错误，不关闭模态。
- 箱子记录保存失败时保留输入内容，显示中文安全错误。
- 图片上传失败时明确说明箱子记录已经保存，并允许重试。
- 二维码生成失败时保留箱号与链接，并允许重新生成。
- 关闭未成功创建的模态不产生记录，也不刷新列表。

## 7. 无障碍与响应式

- 模态使用 `role="dialog"`、`aria-modal="true"` 和可访问标题。
- 所有关闭和完成操作具有明确可访问名称，触控目标至少 44px。
- 提交、上传和二维码状态通过 `role="status"` 或 `role="alert"` 公告。
- 320px 宽度下无横向滚动；移动底部导航不会遮挡模态操作区。
- 尊重现有 reduced-motion 规则，不增加必要性不足的进入动画。

## 8. 验收标准

- 所有站内创建入口均在箱子列表上打开模态，不跳转到独立创建页。
- `/app/boxes/new` 自动重定向并打开同一模态。
- 创建、封面上传、成功二维码和下载能力不回归。
- 点击“完成”关闭模态并在列表中显示新箱子。
- Escape、遮罩、焦点限制、背景隔离和滚动恢复行为有自动化测试。
- 保存/上传期间无法意外关闭。
- 桌面、iPhone 和 Pixel 端到端流程通过且无横向溢出。

## 9. 非目标

- 将编辑箱子改为模态窗口。
- 多步骤向导或字段重新设计。
- 修改箱子数据模型、RLS、R2 上传协议或二维码格式。
- 引入全局模态状态管理库。
