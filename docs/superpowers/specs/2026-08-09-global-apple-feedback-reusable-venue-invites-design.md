# 全局 Apple 风格反馈与可复用场地邀请设计

日期：2026-08-09
状态：已确认，待实现计划

## 目标

统一 Nomo 桌面端与移动端的错误反馈体验，使操作错误都呈现为 Apple App 风格的居中系统弹窗；同时把场地邀请改为“最新邀请替换旧邀请、同一二维码可邀请多人”的模型，避免连续点击产生多个邀请并误触发成员名额限制。

本次范围聚焦公共反馈层和场地邀请流程，不重写每个页面的业务布局。字段级输入校验仍保留在字段附近，页面级加载失败仍可使用页面错误状态。

## 视觉与交互设计

### AppleAlert

- 桌面端和移动端共用同一套组件、语义和层级。
- 使用全屏半透明遮罩、轻微背景模糊、圆角浅色卡片和柔和阴影。
- 弹窗包含标题、必要的解决说明和一到两个底部操作按钮。
- 单操作默认为“知道了”；可重试错误使用“取消 / 重试”。
- 弹窗打开时锁定背景滚动并把焦点移入弹窗；关闭后恢复触发控件焦点。
- Escape 和明确的取消按钮关闭弹窗；错误弹窗不允许点击遮罩误触确认。
- 同一错误重复触发时替换现有弹窗，不堆叠通知。

### 全局反馈 API

现有 `MobileFeedbackProvider` 升级为跨端 `FeedbackProvider`，保留操作表单所需的 Action Sheet 能力，但错误和需要用户确认的反馈统一走 `AppleAlert`。页面通过 `useFeedback().error()`、`useFeedback().confirm()` 和 `useFeedback().dismiss()` 触发，不直接创建各自的错误浮层。

错误适配器把 Supabase 错误码、递归 `cause`、网络异常和未知异常转换成双语产品文案。至少覆盖：成员名额已满、邀请已过期、邀请已撤销、权限不足、网络失败、保存失败、删除失败和分享失败。

## 邀请模型

### 创建与替换

保留现有 `create_venue_invite(uuid)` 调用入口，并在新的 forward-only migration 中将其改为原子“撤销旧邀请并创建新邀请”操作：

1. 校验当前用户是场地所有者。
2. 使用现有场地级 advisory lock，撤销该场地所有未使用、未撤销、未过期的旧邀请。
3. 创建一个新的 24 小时有效邀请，标记为可复用。
4. 记录邀请创建审计事件。
5. 只返回新邀请的 token、二维码所需 URL 和过期时间。

前端创建按钮在第一次点击后立即禁用；同一进行中的请求只允许存在一个。创建失败不清空当前已展示的有效邀请；创建成功后才替换二维码并刷新邀请列表，因此连续点击十次最多产生一个请求和一个有效二维码。

### 多人接受

新邀请在有效期内可以被多位不同用户使用，直到场地满员、过期或被所有者撤销。数据库新增邀请接受记录，保存每次成功加入的用户和时间；原有已经使用过的旧版单次邀请保持单次语义。

`accept_venue_invite(text)` 每次调用都在事务锁内重新检查：

- 当前用户是否已经是成员；
- 邀请是否存在、过期或撤销；
- 场地是否仍有席位；
- 当前用户是否为场地所有者。

同一用户重复扫码返回 `already_member`，不创建重复成员；满员返回 `venue_member_limit_reached`。成员加入后刷新场地成员数、可用席位和邀请状态。

### 分享与复制

二维码、复制和系统分享均使用当前最后一次成功创建的邀请。复制或分享进行中按钮禁用，避免重复打开系统分享面板；失败统一进入 AppleAlert。关闭分享弹窗不会创建新邀请，也不会恢复旧邀请。

## 数据流

```text
页面操作
  -> 业务 API / React Query mutation
  -> 错误适配器
  -> FeedbackProvider
  -> AppleAlert（桌面 / 移动共用）

创建邀请
  -> create_venue_invite（锁定场地、撤销旧邀请、创建可复用新邀请）
  -> 返回最新 token
  -> 更新二维码 / 分享链接 / 邀请列表

扫码加入
  -> accept_venue_invite（锁定场地、重新检查席位）
  -> 写入成员与邀请接受记录
  -> 刷新成员数和访问权限
```

## 错误处理

- `venue_member_limit_reached`：提示“成员名额已满”，说明旧邀请也会占用席位，并给出撤销旧邀请或移除成员的行动建议。
- `venue_invite_expired` / `venue_invite_revoked` / `venue_invite_missing`：提示邀请不可用，并提供返回场地或重新获取邀请的入口。
- `venue_access_denied` / `venue_owner_required`：提示无权限并安全返回场地列表。
- 网络错误：提示网络异常，提供“重试 / 取消”。
- 未知错误：显示稳定的通用文案，不把 Supabase 原始错误直接暴露给用户。

## 测试与验收

### 前端

- AppleAlert 桌面端、移动端渲染一致，焦点、Escape、取消、重试行为一致。
- 错误适配器覆盖已知错误码、嵌套 `cause` 和未知异常。
- 连续点击创建邀请只调用一次 mutation。
- 新邀请成功后旧邀请不再有效，二维码只显示最新 token。
- 复制/分享按钮在请求期间禁用，失败显示 AppleAlert。

### 数据库

- 新建邀请会撤销旧的未使用邀请。
- 同一可复用二维码可让不同用户依次加入。
- 同一用户重复接受返回 `already_member`。
- 满员、过期、撤销、旧版单次邀请的语义保持正确。
- 并发接受只产生合法成员，不超过席位上限。

### 发布前验证

运行前端 Vitest、数据库 pgTAP、Playwright 桌面/iPhone/Pixel、类型检查、Lint 和生产构建。数据库和真实 Stripe/Supabase 环境不可用时必须在报告中明确记录，不得将静态检查表述为运行时验证。

## 非目标

- 不在本次工作中改造所有页面的导航、卡片和表单布局。
- 不改变 AI Credits、箱子权益或已有成员权限模型。
- 不删除历史邀请、成员或审计数据。
