# 新手引导弹窗与全局多语言设计

## 目标

本次改造解决两个相互关联但边界清晰的问题：

1. 新手引导不再插入 Dashboard 的业务列表，而是只对新用户首次进入时显示响应式弹窗；关闭后不再自动打扰，但用户可以手动重新打开。
2. 全系统统一支持简体中文和 English，不区分登录与否，所有用户界面使用同一个语言状态和同一套翻译字典。

## 已确认的产品决策

- 新手弹窗采用方案 A：桌面端居中弹窗，移动端底部抽屉。
- 弹窗只自动展示一次；点击关闭或“稍后再说”后不再自动出现。
- Dashboard 保留“新手指南”入口，用户可以随时手动打开弹窗。
- 新手第一次自动展示只解释当前第一步，并将用户带到创建空间流程。
- 全局语言只有 `zh-CN` 和 `en-US`。
- 语言状态不区分登录与否，使用统一的浏览器本地偏好。
- 用户创建的空间、箱子、物品名称属于用户内容，不由界面翻译层改写。

## 一、新手引导弹窗

### 1. 触发条件

Dashboard 在空间、箱子和物品查询完成后决定是否展示自动引导：

- 当前用户的 `profiles.onboarding_welcome_seen_at` 为空；
- 当前账户仍处于基础激活前，至少满足“没有任何物品”的新手状态；
- 当前路由是 Dashboard，避免用户从深层链接进入时被打断。

弹窗展示后立即调用 `mark_onboarding_welcome_seen()`，由数据库记录首次展示时间。调用失败时仍允许用户继续使用当前页面，但不会把本次展示误记为成功；下次 Dashboard 加载时可以重试。

已有账户如果已经有物品，不会因为新字段为空而弹出欢迎引导。这样不会打扰已完成核心流程的老用户。

### 2. 交互状态

`OnboardingWelcomeDialog` 只维护展示层状态，进度仍从现有业务数据实时推导：

| 状态 | 行为 |
| --- | --- |
| 首次自动展示 | 展示标题、三步概览和“开始创建空间”主按钮 |
| 用户关闭 | 关闭弹窗，不再自动展示；Dashboard 显示“新手指南”入口 |
| 点击主按钮 | 先关闭弹窗，再跳转 `/app/spaces?create=1` |
| 手动打开 | 根据当前空间、箱子、物品数据显示对应进度和下一步 |
| 已完成基础激活 | 自动弹窗和手动入口都不再显示 |

弹窗使用现有 `ResponsiveEditorDialog` / `ConfirmDialog` 的可访问性约定：焦点进入弹窗、Esc 关闭、遮罩点击关闭、关闭后恢复触发按钮焦点，并设置正确的 `role="dialog"`、`aria-modal` 和标题关联。

### 3. 响应式布局

- 桌面端使用居中卡片，最大宽度约 32rem，遮罩覆盖整个应用内容区。
- 移动端使用底部抽屉，圆角只保留顶部，内容区域支持安全区和内部滚动，主按钮保持全宽且满足触控尺寸。
- 两端共享文案和步骤组件，只调整容器定位、间距和操作按钮布局。
- Dashboard 不再渲染 `OnboardingProgressCard`，避免引导卡片出现在统计、空间和箱子列表之间。

### 4. 数据库变更

新增迁移 `supabase/migrations/202608080001_onboarding_welcome.sql`：

- 给 `public.profiles` 增加可空的 `onboarding_welcome_seen_at timestamptz`；
- 新增 `public.mark_onboarding_welcome_seen()`，只允许当前认证用户执行；
- RPC 使用幂等更新：已有时间不被覆盖，首次为空时写入当前时间；
- 保持现有 profiles RLS，不开放匿名访问。

同步更新 `apps/web/src/lib/database.types.ts` 和 profile API 类型，新增 `markOnboardingWelcomeSeen()`。

## 二、全局多语言

### 1. 语言状态层

新增 `apps/web/src/i18n/`：

- `locale.ts`：语言枚举、存储 key、解析和回退逻辑；
- `I18nProvider.tsx`：维护当前语言、切换方法和 `document.documentElement.lang`；
- `useI18n.ts`：提供 `t(key, params?)`、`locale` 和 `setLocale`；
- `messages/zh-CN.ts`、`messages/en-US.ts`：类型化翻译字典。

`I18nProvider` 放在 Router 和 AuthProvider 外层，确保落地页、认证页、法律页面和登录后应用共享同一个状态。初始化顺序：有效的 `localStorage` 偏好 → `zh-CN` 默认值。localStorage 不可用时使用内存状态，不阻塞应用启动。

切换语言时同步：

- `document.documentElement.lang`；
- 当前页面标题；
- 所有 `useI18n()` 消费者；
- `localStorage` 中的统一偏好。

### 2. 账户语言与 AI 输出

界面语言以浏览器本地偏好为主，不因登录状态切换或重置。登录后如果 profile 已存在，则在用户主动切换语言时调用现有 `update_profile_locale`，把同一语言同步给后端，用于 AI 新会话的输出语言；同步失败不回滚界面切换，并显示非阻塞错误反馈。

在没有本地偏好但已有 profile 语言时，登录后的首次初始化可以采用 profile 语言作为一次性默认；一旦用户在当前浏览器选择语言，后续以本地偏好为准。

### 3. 翻译范围

迁移所有用户界面可见文案，包括：

- AppShell 桌面和移动导航；
- Dashboard、空间、箱子、搜索、扫码、打印、资料和设置；
- 所有表单 label、placeholder、校验错误、空状态、加载状态、toast 和对话框；
- 登录、注册、找回密码、重置密码；
- 隐私政策和服务条款页面的导航与语言选择器；
- 无障碍 `aria-label`、`role` 描述和页面标题。

不迁移用户输入数据、数据库中的用户内容名称，也不把内部枚举 key 改成自然语言。业务枚举通过翻译 key 映射展示，存储值保持稳定。

### 4. 共享语言切换器

新增 `LanguageSwitcher`，只接收当前语言和切换回调，不自行读取登录状态。入口放在：

- 落地页导航；
- AuthLayout 的认证页工具区；
- AppShell 桌面侧边栏账户区域；
- 移动端“我的 → 通用”；
- 法律 Markdown 页头部。

各处使用相同的 `aria-label`、选项值和视觉规范；移动端不额外复制一套语言逻辑。

### 5. 缺失翻译策略

生产环境缺失 key 回退 `zh-CN`，避免空白按钮或无法操作的页面。开发环境通过 `console.warn` 记录缺失 key 和当前语言；测试环境提供断言工具，确保新增页面的关键可见文案在两种语言中都有值。

## 三、实施边界与顺序

1. 先建立 i18n 状态层、消息类型和共享 `LanguageSwitcher`，迁移落地页与认证页作为最小闭环。
2. 新增 onboarding 数据迁移、RPC、API 和弹窗组件，移除 Dashboard 内嵌引导卡片。
3. 按路由批量迁移登录后页面，优先迁移 AppShell、Dashboard、空间、箱子和搜索，再迁移扫描、打印、资料与设置。
4. 最后迁移错误映射、业务枚举、无障碍标签和测试夹具，补齐中英文覆盖检查。

每个阶段都保持两种语言可运行，不允许出现只翻译标题而按钮、错误和空状态仍为另一种语言的混合页面。

## 四、测试与验收

### 新手引导

- 新账号首次打开 Dashboard 自动显示对话框；
- 桌面端使用居中弹窗类名，移动端使用底部抽屉类名；
- 关闭后同一账号重新进入 Dashboard 不再自动显示；
- “新手指南”入口可以重新打开；
- 点击主按钮关闭弹窗并进入创建空间路径；
- 已有物品的账户不显示自动欢迎弹窗；
- 空间、箱子、物品进度变化后手动弹窗显示正确下一步；
- RPC 重试、重复调用和失败反馈均有覆盖。

### 多语言

- 初始化默认中文，切换 English 后刷新仍保持 English；
- 未登录落地页、认证页和法律页可以独立切换语言；
- 登录后应用导航、页面标题、表单、弹窗、错误、空状态和移动导航同步切换；
- 语言切换不会改变用户内容名称和数据库枚举值；
- 缺失 key 在生产回退中文，在开发和测试环境可观测；
- 语言切换到 profile 的同步失败不会阻塞界面；
- 桌面和移动断点下语言选择器与弹窗无横向溢出。

## 五、上线注意事项

- 新增数据库迁移必须先在目标 Supabase 环境执行并刷新类型；
- `onboarding_welcome_seen_at` 只记录引导展示，不代表用户完成空间、箱子或物品任务；
- 翻译字典中的产品、法律和支付文案需在发布前完成中文与英文校对；
- 后端 AI 输出语言依赖 profile 同步，界面语言本身不需要登录权限；
- 后续新增页面必须同时提交两种语言字典和缺失 key 测试。
