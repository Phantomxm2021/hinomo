# Nomo 全站移动端与加载体验统一设计

日期：2026-08-01

状态：设计已确认

适用范围：全部登录后页面、公开箱子详情、扫描流程与创建箱子流程

## 1. 目标

本轮统一解决六类体验偏差：扫描页暴露技术性输入框、数据加载阶段缺少稳定占位、创建箱子成功后出现多余二维码结果、箱子目录工具栏过重、移动端页面与暖色家庭设计语言不一致，以及移动端顶部重复导航入口。

成功后的体验应满足：用户只看到与当前任务有关的操作；首次数据加载时页面结构稳定；创建箱子后立即回到更新后的目录；移动端所有登录后页面共享同一套标题、留白、卡片和导航规则。

## 2. 范围与边界

本次包含：

- 删除扫描页的手动二维码地址输入区。
- 为所有查询驱动页面和授权图片增加结构化 Skeleton。
- 创建箱子成功后关闭模态、刷新目录并显示轻量成功反馈。
- 保留创建期间的封面上传重试能力。
- 全部箱子页保留搜索与空间筛选，移除排序控件和排序状态。
- 全站登录后移动布局对齐暖色家庭设计稿，并移除移动端右上角空间按钮。
- 覆盖 320、360、390、768、1024 和 1440 像素断点。

本次不包含：

- 修改 Supabase、RLS、R2、二维码内容或数据库结构。
- 新增二维码文本粘贴、相册识别或其它扫描替代入口。
- 重做桌面端已确认的侧栏、首页或打印工作台。
- 新增排序方式或服务端排序 API。

## 3. 扫描页

扫描页只保留：

1. `扫描箱子标签` 页面标题与简短说明。
2. 摄像头画面。
3. 权限请求、识别中和识别失败状态。
4. 识别成功后的箱子路由跳转。

彻底删除 `手动输入二维码地址` 标签、输入框、提交按钮及“重新尝试相机”按钮。相机权限被拒绝时只给出浏览器权限说明。识别到无效或非 Nomo 二维码时使用置顶的非阻断提示，相机保持运行，用户无需操作即可继续扫描。

二维码地址格式有效但对应箱子不存在或当前用户无权访问时，落地页显示“箱子不存在或无法访问”，唯一主操作为“重新扫码”，点击后返回 `/app/scan`。不得把该操作实现为重复请求同一个箱子；关闭提示后也不得留下空白页面。网络请求失败与内容不存在必须分开处理，只有网络失败保留原地重试。

移动端画面使用全宽卡片、稳定的 4:5 或设备可容纳比例，状态内容紧贴摄像头卡片，不额外引入顶部操作按钮。

## 4. 全站 Skeleton 系统

新增共享 `Skeleton` 基础组件，提供以下可组合形态：

- 文字行：标题、正文与元信息宽度。
- 媒体块：方形封面、头像与二维码区域。
- 列表行：图标/选择位、两行文本与尾部元信息。
- 卡片：与正式卡片相同圆角、边框和内部间距。

Skeleton 使用现有 `canvas`、`surface`、`line` 与 muted 派生色，不引入新颜色。默认使用轻微脉冲动画；在 `prefers-reduced-motion: reduce` 下关闭动画。

共享页面级骨架按真实布局组合，而不是只放一个居中的灰色矩形：

- 首页：统计卡、空间卡和最近箱子卡。
- 空间页：标题工具栏、空间选择/卡片与布局区域。
- 全部箱子：标题、搜索/空间筛选和箱子卡片网格。
- 箱子详情、编辑与公开详情：标题、元信息、封面和物品列表。
- 搜索：结果分区与结果行。
- 打印：选择器与 A4 纸张轮廓。
- 用户资料与授权图片：头像或媒体占位。

首次无数据加载时显示 Skeleton。已有数据后台刷新时继续显示旧数据，不以 Skeleton 覆盖内容。错误和空状态继续使用明确错误/空状态，不用 Skeleton 掩盖。

每个加载区保留可访问的 `role="status"` 与屏幕阅读器标签；视觉占位本身 `aria-hidden="true"`。

## 5. 创建箱子完成流程

创建流程保留现有模态、表单校验、R2 上传和离开保护。

成功路径调整为：

```text
提交表单 → 创建箱子 → 上传封面（如有） → 关闭模态
       → invalidate/refetch boxes → 列表显示新箱子 → 轻量成功提示
```

不再生成或展示创建结果二维码、公开链接、下载 PNG 或“重新生成”操作。二维码仍可从打印标签页按需生成。

若箱子已创建但封面上传失败：

- 模态保持打开。
- 明确说明箱子记录已创建但封面未完成。
- 保留当前文件和重试上传操作。
- 重试成功后关闭模态并刷新列表。

关闭成功后的模态时恢复触发按钮焦点；列表刷新失败时保留已有目录并显示可重试提示。

## 6. 全部箱子目录

工具栏只保留：

1. 搜索输入：名称、编号、空间和位置。
2. 空间筛选：全部空间或指定空间。
3. 条件清除操作。

移除排序下拉框、`sort` URL 参数、排序解析和客户端排序分支。目录使用 API 返回的稳定顺序。读取旧的 `sort` 参数时将其清除，不再影响结果。

移动端工具栏纵向排列，搜索框占满宽度，空间筛选与清除操作位于下一行。桌面端保持紧凑横向排列。

## 7. 全站移动端布局

AppShell 移动端顶部只显示 Nomo 品牌，删除右上角“我的收纳空间”圆形按钮。底部五项导航继续承担页面切换，中央扫码入口保持抬高样式。

所有登录后页面统一：

- 页面左右留白 20px；320px 设备可缩小到 16px，但不得产生横向滚动。
- Eyebrow、页面标题、说明、分区标题沿用现有 typography token。
- 主操作最小高度 48px，普通触控目标不低于 44px。
- 卡片使用 `rounded-card`、细 `line` 边框和 `surface` 背景；非浮层不使用重阴影。
- 页面底部避让固定导航与安全区。
- 桌面专属的摘要、批量工具和多列工作台在小于 `lg` 时替换为移动任务流，不简单缩放桌面版。

逐页检查首页、空间、箱子目录、箱子详情/编辑、搜索、扫描和打印。公开箱子详情虽不使用 AppShell，也应采用相同的移动留白、卡片和 typography。

## 8. 组件与数据流

新增共享展示组件：

- `Skeleton`：单个视觉占位。
- `SkeletonGroup` 或页面局部骨架组件：提供可访问加载状态，并组合多个 Skeleton。

页面继续拥有自己的查询与错误处理，不新增全局加载 store。各页面根据真实结构渲染局部骨架，避免一个万能页面骨架与所有布局脱节。

箱子创建成功由模态通过现有完成回调通知 `BoxesPage`；`BoxesPage` 负责查询失效、刷新、关闭模态和成功反馈。上传失败仍留在 `BoxForm` 内部处理。

## 9. 状态与错误处理

- 首次查询：结构化 Skeleton。
- 后台刷新：保留真实数据，不闪回 Skeleton。
- 查询失败：现有错误与重试。
- 查询成功但无数据：现有空状态。
- 授权图片加载失败：保留替代内容，不无限显示 Skeleton。
- 扫描权限失败：只展示权限说明，不提供页面内重试按钮。
- 创建成功：关闭模态、刷新列表、成功提示。
- 创建后上传失败：模态内重试，不显示二维码结果。

## 10. 测试与验收

### 10.1 单元与组件测试

- `Skeleton` 的可访问状态、视觉元素隐藏和 reduced-motion 类。
- 所有查询驱动页面首次 pending 时出现 Skeleton，成功后移除。
- 已有数据 refetch 时不覆盖真实内容。
- 扫描页不存在二维码地址输入或提交行为。
- 扫描页不存在“重新尝试相机”按钮；无效二维码提示后仍可继续识别有效二维码。
- 创建成功后不请求二维码、不显示结果页，关闭模态并刷新列表。
- 上传失败保留模态并可重试。
- 箱子工具栏不存在排序控件；搜索与空间筛选继续组合工作。
- AppShell 移动 header 不存在右上角空间按钮。

### 10.2 浏览器验收

- 1440×900、1024×768：桌面布局无回归。
- 768×1024、390×844、360×800、320×568：移动端标题、卡片、表单、底部导航和 Skeleton 无重叠、无遮挡、无横向滚动。
- 移动端所有登录后路由无右上角空间按钮。
- 创建箱子完成后目录出现新箱子，不出现二维码成功页面。
- 扫描页仅提供相机流程。

### 10.3 回归门禁

- 全量 Vitest。
- TypeScript 与 Oxlint。
- 生产构建。
- Playwright desktop、iPhone、Pixel。
- `git diff --check` 与工作树审计。

## 11. 成功标准

全站数据加载不再以文字或空白替代真实结构；移动端所有登录后页面与已确认的暖色家庭设计语言一致；扫描和创建箱子流程只保留完成任务所需步骤；箱子目录更简洁，同时搜索与空间筛选能力保持不变。
