# QR Code 智能收纳清单管理系统设计

**日期：** 2026-07-29  
**状态：** 待用户复核  
**依据：** `docs/QR_Code_智能收纳清单管理系统_PRD.md`

## 1. 目标

实现一个移动优先的 React PWA，让用户通过二维码为实体收纳箱建立数字身份，并完成“注册登录 → 创建空间 → 创建箱子 → 生成并打印二维码 → 扫码查看 → 维护物品 → 全局搜索”的 MVP 闭环。

后端使用 Supabase Auth、Postgres、RLS、RPC、Trigger 和定时任务。用户上传的图片及后续媒体文件统一存入私有 Cloudflare R2 Bucket，不使用 Supabase Storage，也不使用 Supabase Edge Function。

## 2. MVP 范围

### 2.1 包含

- 邮箱和密码注册、登录、登出及密码重置。
- 创建、修改、查看和删除空间。
- 创建、修改、查看和删除箱子。
- 箱子公开性设置：`public` 或 `private`，默认 `private`。
- 箱子二维码生成、PNG 下载、单箱 PDF、多个已有箱子的批量 PDF。
- 公开箱匿名扫码查看；私有箱仅箱主登录后查看。
- 任何箱子和物品编辑操作都要求箱主登录。
- 物品新增、查看、修改和删除。
- 箱子封面及物品图片上传到 Cloudflare R2。
- 登录用户在自己的全部空间和箱子中全局搜索物品。
- 关键增删改操作写入活动日志。
- 响应式 PWA、添加到主屏幕和移动设备相机扫码。

### 2.2 不包含

- 家庭成员邀请、编辑者或查看者角色。
- AI 图片识别、NFC、RFID、自动装箱和企业库存流程。
- 层级空间；空间只提供一层分组，箱子的具体位置使用自由文本。
- 离线修改和自动同步。
- 批量创建箱子。
- 完整的活动日志管理界面。
- iOS 或 Android 原生应用封装。

## 3. 技术方案

### 3.1 技术栈

- React、TypeScript、Vite。
- React Router 管理公开与登录后路由。
- TanStack Query 管理服务端数据、缓存和失效。
- React Hook Form 与 Zod 管理表单和共享校验。
- Supabase JavaScript SDK 访问 Auth、Postgres 和 RPC。
- Tailwind CSS 与可访问的无样式组件构建响应式界面。
- `vite-plugin-pwa` 提供 manifest 和应用外壳缓存。
- QR 生成库输出 Canvas/PNG，PDF 库生成单箱及批量打印模板。
- 浏览器图片压缩库在上传前转码并限制文件尺寸。
- 浏览器二维码扫描库调用移动设备相机。
- Vitest、React Testing Library、pgTAP 和 Playwright 负责自动化验证。

### 3.2 系统边界

React PWA 通过 Supabase SDK 直接访问数据库。前端只持有 Supabase 匿名密钥；所有数据授权由 RLS 和受限 RPC 在数据库层强制执行，不能依赖前端按钮显隐。

Cloudflare R2 Bucket 始终保持私有。R2 访问密钥存入 Supabase Vault。数据库 RPC 根据当前用户、箱子公开性和对象路径签发短时 AWS SigV4 URL；浏览器使用该 URL 直接上传或下载 R2 对象。Trigger 只负责写入媒体清理队列，定时任务异步删除 R2 对象。

## 4. 数据模型

所有业务表使用 UUID 主键和带时区时间戳。用户身份来自 Supabase `auth.users`，MVP 不重复维护密码或认证信息。

### 4.1 `spaces`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `owner_id` | uuid | 引用 `auth.users.id`，不可为空 |
| `name` | text | 同一用户下非空，去除首尾空白后长度 1–80 |
| `description` | text | 可空，最长 500 字符 |
| `created_at` | timestamptz | 默认当前时间 |
| `updated_at` | timestamptz | 自动维护 |

非空空间不能删除。用户必须先移动或删除其中箱子，避免误删整组数据。

### 4.2 `boxes`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `public_id` | uuid | 随机且稳定的二维码路由标识，唯一、不可变 |
| `box_code` | text | 面向用户的唯一编号，例如 `BX-00001` |
| `owner_id` | uuid | 引用 `auth.users.id`，不可为空 |
| `space_id` | uuid | 引用 `spaces.id`，删除受限 |
| `name` | text | 长度 1–120 |
| `category` | text | 可空，最长 80 字符 |
| `location` | text | 空间内具体位置，可空，最长 200 字符 |
| `description` | text | 可空，最长 1000 字符 |
| `visibility` | enum | `public` 或 `private`，默认 `private` |
| `cover_object_key` | text | 可空，R2 对象键 |
| `cover_mime_type` | text | 可空，允许 JPEG、PNG、WebP |
| `cover_size_bytes` | bigint | 可空且大于 0 |
| `created_at` | timestamptz | 默认当前时间 |
| `updated_at` | timestamptz | 自动维护 |

创建箱子时由数据库安全生成 `box_code`，前端不能自行决定编号。二维码内容为 `${PUBLIC_APP_ORIGIN}/b/${public_id}`。重新生成二维码只重新导出同一地址，不轮换 `public_id`，已经打印的标签持续有效。

### 4.3 `items`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `box_id` | uuid | 引用 `boxes.id`，箱子删除时级联删除 |
| `name` | text | 长度 1–120 |
| `category` | text | 可空，最长 80 字符 |
| `quantity` | integer | 必须大于 0，默认 1 |
| `description` | text | 可空，最长 1000 字符 |
| `image_object_key` | text | 可空，R2 对象键 |
| `image_mime_type` | text | 可空，允许 JPEG、PNG、WebP |
| `image_size_bytes` | bigint | 可空且大于 0 |
| `created_at` | timestamptz | 默认当前时间 |
| `updated_at` | timestamptz | 自动维护 |

### 4.4 `activity_logs`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `actor_id` | uuid | 操作用户；系统清理操作可空 |
| `box_id` | uuid | 相关箱子，可空 |
| `action` | enum | `create`、`update` 或 `delete` |
| `entity_type` | enum | `space`、`box` 或 `item` |
| `entity_id` | uuid | 被操作实体 ID |
| `snapshot` | jsonb | 仅保留审计所需字段，不保存签名 URL 或密钥 |
| `created_at` | timestamptz | 默认当前时间，不允许更新 |

活动日志由数据库 Trigger 写入，普通客户端不能插入、修改或删除。

### 4.5 `media_cleanup_jobs`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `object_key` | text | 待删除 R2 对象键，唯一 |
| `attempts` | integer | 默认 0 |
| `status` | enum | `pending`、`processing`、`completed` 或 `failed` |
| `next_attempt_at` | timestamptz | 下次重试时间 |
| `last_error` | text | 可空，经过脱敏的错误摘要 |
| `created_at` | timestamptz | 默认当前时间 |
| `updated_at` | timestamptz | 自动维护 |

箱子封面或物品图片被替换、清空、级联删除时，Trigger 将旧对象键写入该表。定时数据库任务分批处理并指数退避重试，达到最大次数后保留 `failed` 记录供运维检查。

## 5. 数据权限

### 5.1 空间

- 只有 `owner_id = auth.uid()` 的用户可读取、创建、修改或删除自己的空间。
- 创建和更新时，`owner_id` 必须等于 `auth.uid()`。

### 5.2 箱子

- 匿名用户和其他登录用户只能读取 `visibility = 'public'` 的箱子。
- 箱主可以读取自己的公开或私有箱。
- 只有箱主可以创建、修改或删除箱子。
- 新建或移动箱子时，目标空间必须属于当前用户。
- 对无权读取的私有箱，应用统一返回“无权限或内容不存在”，不泄露其存在性。

### 5.3 物品

- 当所属箱子公开时，匿名用户和其他登录用户可以只读物品。
- 箱主可读写自己箱子中的物品。
- 插入或移动物品时，目标箱子必须属于当前用户。

### 5.4 活动与清理

- 箱主可读取自己箱子的活动日志，但 MVP 不提供完整日志页面。
- 客户端不能直接写活动日志或媒体清理任务。
- 清理任务仅允许受控数据库函数访问。

## 6. R2 媒体设计

### 6.1 对象路径

对象键由数据库返回，格式为：

```text
users/{owner_id}/boxes/{box_id}/{media_kind}/{random_uuid}.{extension}
```

`media_kind` 只允许 `cover` 或 `item`。RPC 必须从 `auth.uid()` 和数据库归属关系构造路径，不能信任客户端提交的 `owner_id` 或任意对象键。

### 6.2 上传流程

1. 用户选择 JPEG、PNG 或 WebP 图片。
2. React 校验原文件类型和大小，并压缩为 WebP；保留透明度或格式兼容性时可保留 PNG。
3. React 调用 `create_media_upload` RPC，提交箱子 ID、媒体类型、MIME 类型和字节数。
4. RPC 验证登录状态、箱子所有权、MIME 类型和大小上限，从 Vault 读取 R2 密钥，并返回对象键及短时 SigV4 `PUT` URL。
5. 浏览器直接上传到 R2，上传请求的 `Content-Type` 必须与签名一致。
6. React 调用 `confirm_media_upload` RPC，提交对象键和对应箱子或物品 ID。
7. RPC 再次验证路径归属后写入媒体元数据。旧对象由 Trigger 加入清理队列。

箱子封面和物品图片的压缩后大小上限统一为 5 MiB。签名 URL 默认 5 分钟失效。R2 CORS 只允许已配置的应用来源执行所需的 `PUT`、`GET` 和 `HEAD` 请求。

### 6.3 下载流程

1. React 通过箱子的 `public_id` 和媒体引用调用 `create_media_download` RPC。
2. RPC 查询箱子可见性：公开箱允许匿名调用；私有箱要求 `owner_id = auth.uid()`。
3. RPC 返回 5 分钟有效的 SigV4 `GET` URL。
4. 前端仅在内存中使用该 URL，不将它写入数据库、日志或长期缓存。

### 6.4 清理与失败恢复

- R2 上传成功但 `confirm_media_upload` 失败时会形成孤儿对象。定时任务按对象前缀和数据库引用进行清理。
- 删除或替换媒体只操作数据库引用；Trigger 将旧对象键加入清理队列，避免数据库事务依赖外部网络。
- 清理 R2 失败不回滚用户的数据库操作，而是进入重试。
- RPC 的 SigV4 实现使用固定测试向量和测试 R2 Bucket 验证，避免 URL 编码、时间戳和请求头差异导致签名错误。

## 7. 前端信息架构

### 7.1 公开路由

| 路由 | 用途 |
| --- | --- |
| `/login` | 邮箱密码登录 |
| `/register` | 邮箱密码注册 |
| `/forgot-password` | 发起密码重置 |
| `/reset-password` | 设置新密码 |
| `/b/:publicId` | 二维码箱子详情；公开箱匿名访问，私有箱要求箱主登录 |

### 7.2 登录后路由

| 路由 | 用途 |
| --- | --- |
| `/app/boxes` | 当前用户全部箱子 |
| `/app/boxes/new` | 创建箱子并生成二维码 |
| `/app/boxes/:id/edit` | 修改箱子资料和公开性 |
| `/app/search` | 全局物品搜索 |
| `/app/spaces` | 空间管理 |
| `/app/print` | 选择多个已有箱子并生成 PDF |
| `/app/profile` | 账号信息和退出登录 |
| `/app/scan` | 调用相机扫描二维码 |

移动端主导航为“箱子、搜索、空间、我的”，扫码作为显著快捷操作。桌面端保持相同路由和信息层级，将底部导航切换为侧栏，并将列表适配为多列布局。

### 7.3 核心页面行为

- 扫码箱子页首先展示名称、空间、具体位置、封面、备注、物品种类数、数量总和及物品列表。
- 匿名查看公开箱时隐藏编辑控件，并提供“登录后管理”入口。
- 私有箱未登录时显示登录入口；登录但不是箱主时仍显示统一无权限状态。
- 箱主在同一箱子详情页新增、编辑或删除物品，减少扫码后的跳转层级。
- 新增与编辑表单在窄屏使用全屏页面或底部抽屉，在宽屏使用对话框或独立页面。
- 删除物品和箱子必须二次确认；删除箱子的确认文案显示将删除的物品数量。
- 离开有未保存内容的表单前提示用户。

## 8. 搜索

全局搜索只向登录用户开放，仅搜索当前用户拥有的物品。搜索字段包括物品名称、分类和备注，不搜索其他用户的公开箱。

结果至少显示：物品名称、数量、箱子名称、空间名称和箱子具体位置。点击结果进入对应箱子详情。数据库为归属过滤及常用搜索字段建立索引；MVP 使用 PostgreSQL 文本搜索和模糊匹配，不引入外部搜索服务。

## 9. 二维码与打印

- 二维码只编码稳定的公开路由，不包含箱子内容、用户 ID 或权限信息。
- PNG 下载适合单独打印和分享。
- 单箱 PDF 标签包含二维码、`box_code`、箱子名称、空间和具体位置。
- 批量 PDF 允许用户勾选多个已有箱子，按固定纸张尺寸排版多个标签。
- 生成过程在浏览器完成，不把二维码图片上传到数据库或 R2。
- PDF 生成前验证选择不为空；大量箱子分批渲染并显示进度，避免移动浏览器长时间无响应。

## 10. PWA 与移动设备

- 使用移动优先断点、至少 44×44 CSS 像素的触控区域和安全区适配。
- Manifest 提供名称、图标、主题色和 standalone 展示模式。
- Service Worker 只缓存应用外壳和带版本的静态资源，不缓存私有 API 响应、签名 URL或用户图片。
- 断网时可以打开已缓存的应用外壳并显示离线状态，但不支持离线读取或编辑业务数据。
- 相机扫码必须在 HTTPS 或 localhost 环境运行；权限拒绝后提供手动输入二维码地址的替代方式。

## 11. 错误处理

- Auth 错误转换为清晰的中文提示，不直接显示原始数据库错误。
- RLS 拒绝和资源不存在统一映射为无权限状态。
- 表单同时执行客户端校验和数据库约束；数据库是最终校验边界。
- 网络请求失败提供明确的重试操作，不进行无限自动重试。
- 图片上传显示压缩、上传和确认三个阶段；任一阶段失败均允许用户重选或重试。
- 删除失败时保留当前列表内容并提示原因；成功后再使相关 Query 缓存失效。
- PWA 更新可用时提示刷新，不在用户编辑表单时强制刷新。

## 12. 测试策略

### 12.1 单元与组件测试

- 表单字段边界、数量正整数和文件限制。
- 公开/私有状态对应的按钮和提示。
- 二维码内容稳定性、PNG 导出参数和 PDF 标签数据映射。
- 全局搜索结果到箱子路由的映射。
- 图片压缩、上传状态机和失败重试。

### 12.2 数据库与权限测试

使用本地 Supabase 和 pgTAP 验证：

- 匿名只能读取公开箱及其物品。
- 箱主可以读取和修改自己的公开、私有箱及物品。
- 其他登录用户不能修改公开箱，也不能读取私有箱。
- 用户不能把箱子挂入其他用户空间，或把物品挂入其他用户箱子。
- 活动日志和媒体清理任务不能由普通客户端伪造。
- 空间非空时删除失败，删除箱子时物品级联删除并产生媒体清理任务。
- 媒体上传和下载 RPC 拒绝越权对象路径。

### 12.3 R2 集成测试

- 固定 SigV4 测试向量产生确定结果。
- 测试 Bucket 验证签名 PUT、GET 和 DELETE。
- 过期签名、错误 MIME 类型、错误对象路径和跨用户访问均失败。
- 清理任务失败后按退避策略重试，并在成功后标记完成。

### 12.4 端到端与真机测试

Playwright 覆盖注册登录、密码重置、空间和箱子创建、二维码生成、匿名扫码、物品 CRUD、全局搜索、公开性切换、图片上传和批量 PDF。自动化 viewport 至少包含 iPhone、Pixel 和桌面尺寸。

真机验证相机授权与拒绝、二维码识别、添加到主屏幕、图片拍摄上传、PDF 下载、软键盘遮挡和触控操作。

## 13. 部署与运维

- React PWA 部署到 Cloudflare Pages。
- Supabase 项目承载 Auth、Postgres、RLS、RPC、Trigger 和定时任务。
- Cloudflare R2 使用私有 Bucket。
- 本地、测试和生产环境使用独立 Supabase 项目或隔离配置，并使用独立 R2 Bucket。
- 所有数据库对象、RLS、RPC、Trigger、索引和定时任务通过版本化 migration 管理。
- CI 依次执行格式检查、lint、TypeScript 类型检查、单元测试、数据库测试、生产构建和关键 E2E。
- 日志不得记录密码、R2 Secret、完整签名 URL 或用户上传内容。
- R2 Secret 定期轮换；轮换期间允许短暂双密钥过渡，完成后撤销旧密钥。

## 14. 验收标准

1. 新用户可以用邮箱和密码完成注册、登录及密码重置。
2. 登录用户可以创建空间，并在自己的空间内创建箱子。
3. 创建箱子后立即获得稳定二维码，可下载 PNG 和单箱 PDF。
4. 用户可以选择多个已有箱子生成包含正确标签信息的批量 PDF。
5. 未登录用户扫码可查看公开箱及物品，但不能执行任何编辑。
6. 未登录用户不能查看私有箱；箱主登录后可以查看和编辑。
7. 任何其他登录用户都不能编辑公开箱或读取私有箱。
8. 箱主可以新增、修改、删除物品，数量始终为正整数。
9. 箱主可以上传箱子封面和物品图片，文件存入私有 R2，数据库不保存永久公开 URL。
10. 登录用户可以全局搜索自己的物品，并看到箱子、空间、位置和数量。
11. 删除或替换图片后产生清理任务，R2 清理失败不会破坏业务事务并能够重试。
12. PWA 可在主流移动浏览器使用并添加到主屏幕，相机扫码在授权后可用。
