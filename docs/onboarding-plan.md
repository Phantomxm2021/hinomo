# Nomo 新用户引导方案

## 背景

Nomo 的核心数据路径是“场地 → 空间 → 箱子 → 物品”，但新用户第一次进入时，只能看到空的统计和内容区域，缺少一条能够直接完成的下一步路径。桌面端和移动端虽然共享同一套数据，使用场景却不同：桌面端适合建立结构、批量整理和打印标签；移动端适合在实体箱子旁拍照、扫码和快速记录。

本方案的目标不是增加一套独立的新手教程，而是让用户在真实任务中完成第一次有效使用。

## 激活目标

新用户完成以下动作后视为基础激活：

1. 至少创建一个空间；
2. 至少创建一个箱子；
3. 至少记录一件物品。

后续可将“首次搜索”“首次扫码”和“首次打印标签”作为进阶激活指标。

## 统一进度模型

首期不增加数据库状态，直接从业务数据推导进度：

- `hasSpace`：当前场地存在空间；
- `hasBox`：当前场地存在箱子；
- `hasItem`：当前场地至少存在一件物品；
- `nextStep`：依次为创建空间、创建箱子、记录物品或完成。

桌面端和移动端共享相同的进度计算，避免跨设备重复引导。用户在桌面端创建空间后，移动端应直接进入“创建箱子”阶段。

## 桌面端体验

桌面端首页显示完整的“开始使用 Nomo”任务面板：

- 展示三个步骤及完成状态；
- 展示整体进度，如“已完成 1/3”；
- 只保留一个与当前步骤对应的主按钮；
- 第一个箱子创建后，引导用户记录物品；
- 基础激活后隐藏任务面板，恢复常规空间总览。

桌面端后续增强：

- 支持一次选择多个常见空间模板；
- 完成首个箱子后推荐打印二维码标签；
- 提供手机接力二维码，直接打开对应箱子的拍摄页面。

## 移动端体验

移动端首页使用紧凑的“下一步”行动卡：

- 一次只解释并推动一个动作；
- CTA 占满可用宽度，适合单手操作；
- 创建空间使用底部抽屉和常用模板；
- 首次创建箱子时仅要求空间、名称和具体位置；
- 创建成功后优先衔接 AI 装箱或手动添加物品。

移动端不应把打印作为早期主任务。扫码入口在没有箱子时，应引导创建第一个箱子，而不是进入无结果页面。

## 关键路径与文案

### 没有空间

- 标题：`从一个空间开始`
- 说明：`空间可以是客厅、卧室、储藏室，也可以是一组货架。`
- CTA：`创建第一个空间`

### 有空间、没有箱子

- 标题：`创建第一个箱子`
- 说明：`记录它放在哪里、里面有什么，以后就不用再翻找。`
- CTA：`创建第一个箱子`

### 有箱子、没有物品

- 标题：`记录箱内物品`
- 说明：`打开刚创建的箱子，拍照识别或手动添加物品。`
- CTA：`记录箱内物品`

### 前置条件保护

当用户在没有空间时尝试创建箱子，不打开不可完成的箱子表单，直接引导到空间创建流程，并说明“创建箱子前，需要先告诉 Nomo 它放在哪个空间”。

## 分阶段落地

### 第一阶段：消除断点

- 首页增加响应式新手进度卡；
- 首页空状态增加可执行 CTA；
- 空间页空状态增加创建按钮；
- 支持 `/app/spaces?create=1` 直达创建空间；
- 没有空间时拦截创建箱子并转入空间创建流程；
- 为上述路径补充组件测试。

### 第二阶段：降低输入成本

- 空间模板和批量创建；
- 移动端精简箱子表单；
- 创建箱子成功后直接进入箱子详情；
- 移动端优先展示 AI 装箱。

### 第三阶段：跨设备接力

- 桌面端生成手机接力二维码；
- 移动端完成录入后提醒在桌面端打印标签；
- 增加首次搜索、扫码、打印的进阶任务。

### 第四阶段：数据验证

建议记录以下漏斗事件：

1. 注册完成；
2. 新手任务曝光；
3. 创建空间；
4. 创建箱子；
5. 添加第一件物品；
6. 首次搜索或扫码。

核心指标为注册后 24 小时内完成“空间 + 箱子 + 物品”的用户比例，并分别观察桌面端、移动端以及跨设备用户的转化差异。
